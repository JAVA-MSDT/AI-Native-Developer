# Business Plan Analysis & Feature Implementation Prompt Template

## Template Category

**Category:**  
- Business Analysis  
- Product Ownership  
- Feature/Functionality Planning  
- Application Development  
- Requirements Engineering

---

## Prompt

You are a business analyst/product owner/feature planner. Carefully review the provided business plan (as a file path or text) to create a new application, feature, or functionality. Your response should be concise, actionable, and easy to follow, formatted in either Markdown or HTML as specified. Ensure your analysis is comprehensive and provides clear next steps for the team.

**Instructions:**
- Analyze the business plan in detail.
- Structure your response using the sections below.
- Include relevant links or references where appropriate.
- Ensure the response is actionable, clear, and suitable for BA, PO, and cross-functional teams.
- Highlight open questions and any missing information.

**Input:**  
- **Business Plan File Path or Text:** [Insert file path or paste business plan text here]

**Required Output Sections:**

1. **Business Plan**  
   - [Summarize or reference the provided business plan]

2. **Business Requirements**  
   - [List and explain the key requirements]

3. **Business Goals**  
   - [Describe the high-level goals the feature/application aims to achieve]

4. **Business Objectives**  
   - [List measurable objectives aligned with the goals]

5. **Business Value Proposition**  
   - [Explain the value this feature/application brings to users and the business]

6. **Business Risks**  
   - [Identify potential risks and mitigation strategies]

7. **Business Constraints**  
   - [List any constraints (technical, regulatory, budget, etc.)]

8. **Business Assumptions**  
   - [State any assumptions made during planning]

9. **Estimated Timeline**  
   - [Provide a high-level timeline or milestones]

10. **Assessments & Recommendations**  
    - [Provide your assessment of feasibility, market value, and recommendations for moving forward]

11. **Implementation Plan**  
    - [Outline the steps for implementation, including dependencies and priorities]

12. **Proposed Architecture**  
    - [Describe or diagram the proposed technical architecture, if applicable]

13. **JIRA Tickets Outline**  
    - [List or outline suggested JIRA tickets/epics/stories for tracking]

14. **Open Questions**  
    - [List any open questions or areas needing clarification]

15. **Additional Information**  
    - [Include any other relevant details, links to resources, or supporting documentation]

---

**Formatting Constraints:**
- Use Markdown or HTML as specified.
- Use clear headings, bullet points, and concise language.
- Ensure logical flow and easy navigation.
- Avoid unnecessary jargon; make the response accessible to all stakeholders.

---

## Incremental Implementation Plan (Example for HTML/Other Deliverables)

To address latency or complexity in finalizing deliverables (e.g., HTML, code, documentation), break down the task into clear, manageable steps:

1. Create the basic skeleton or structure (e.g., HTML, code module).
2. Apply necessary styling or configuration.
3. Add findings or features incrementally, one at a time.
4. After each addition, review to ensure all findings are included and context is preserved.
5. Continue this process until all findings are incorporated and verified.

By following this step-by-step approach, you can finalize deliverables efficiently and accurately.
