## Template Category

**Category:**  
- Requirements Engineering  
- HTML Document Review & Refactoring  
- Implementation Planning

---

## Prompt

Please review all the information and requirements in the provided HTML analysis file.

**File Path:**  
- [Insert the path or URL to the HTML file to be reviewed, compared, or updated]

**Instructions:**

1. **Refactor the document** to present only the final, up-to-date requirements, removing any outdated, superseded, or conflicting information.
2. **Do not use appendices or reference previous iterations**—present the requirements directly and clearly within the main document.
3. **Maintain the original HTML structure,** but make the content more concise, logically ordered, and easy to follow.
4. **After the requirements section, provide a clear, step-by-step implementation plan** in logical order.
5. **Conclude with a section summarizing the expected impact** of these changes on the system, codebase, or workflow.
6. **(Optional):** Compare the refactored requirements and plan with existing implementations or code base, highlighting any gaps, improvements, or risks.

**Output Specification:**

- The final output should be a single, streamlined HTML document that is ready for use and implementation.
- The document must be concise, logically structured, and self-contained.
- All requirements must be current and actionable.
- The implementation plan should be stepwise and verifiable.
- The impact summary should be clear and relevant to stakeholders.
