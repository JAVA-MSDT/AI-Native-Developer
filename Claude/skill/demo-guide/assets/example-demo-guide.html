Task list — fixed expiry on shared-link banner FE PROJ-203

.../workspaces/acme/shared/<share-token>
  • Filed as a bug, not a feature: the shared-link expiry countdown used to be idle-reset — every filter click or scroll pushed the expiry back out, so a shared link someone kept nudging could stay open indefinitely.
  • It's now a fixed wall-clock timer: it starts once when the page loads and fires on schedule regardless of activity — applying a filter no longer resets it.
The configured expiry on this environment is 30 minutes (sharedLinkTtlMs=1800000 in the environment config) — too long to wait for live. Don't wait: open a new tab and navigate straight to .../shared/expired to show the screen a visitor lands on once it fires (it reads back the same 30-minute figure in its body copy) — then say the fixed timer behind it now fires automatically after 30 minutes, whether or not the visitor is interacting with the page.
The same fixed-timer fix was wired into 4 other shared-view screens in the same commit — same mechanism, nothing further to click: Board view, Calendar view, Task detail (shared), Activity feed.

2. Backend-Only Changes to Narrate

Not clickable in the UI, but worth calling out verbally — mostly platform/security hygiene rather than user-facing behavior.

PROJ-205 · Story · In Review

Stop the reminder job from sending duplicate notifications

The scheduled reminder job used to mark a task as "reminder queued" using the same state as "reminder sent" — so on its next run it could treat a queued reminder as not yet sent and enqueue it again. A new dedicated REMINDER_QUEUED state keeps the two apart, with a matching REMINDER_FAILED give-up if delivery is never confirmed in time.

PROJ-206 · Story · In Review

Platform upgrade: runtime, framework and build tool

Major runtime, framework and build-tool version bump across the API service — touches HTTP client configuration, request/response models, and the build wrapper. No behavior change to call out live; worth a mention as a risk item if asked about platform currency.

PROJ-207 · Sub-task · Done

Dependency bump + vulnerability scan via an internal mirror

A scheduler-locking library was bumped a major version, and the dependency-vulnerability scan task now points at an internal mirror of the vulnerability database instead of requiring a personal API key — unblocks the security scan from running reliably in CI. Build/security tooling only, nothing to click.
